# CloudLight Blizzard 2.1.1

## Release Readiness 人工 GUI 验收清单

本清单用于决定下一正式版本前的人工验收，不会修改版本号、创建 Tag、发布 Release 或上传安装包。建议在安装版和 portable/开发运行各执行一次；涉及真实区服切换或 Drops 登录时，只观察页面和取消操作即可。

总用时约 15 分钟。每项完成后勾选，并记录窗口尺寸、Windows 版本和 DPI。

1. **打开账号（约 1 分钟）**
   - 操作：启动程序，保持在“账号”，点击一次“刷新账号”。
   - 预期：账号页面正常出现；当前账号、已保存账号和账号操作均可见。刷新只更新账号状态，不启动网络诊断、完整快照 Hash、全盘扫描或 Drops Worker。

2. **打开 Diagnostics（约 30 秒）**
   - 操作：进入“诊断中心”。
   - 预期：页面能打开，状态词只使用“正常 / 警告 / 错误 / 信息”，不会把警告显示成系统错误。

3. **开始诊断（约 1 分钟）**
   - 操作：点击“开始诊断”，等待完成；如网络较慢，等待到结果出现。
   - 预期：进度持续更新，直连超时显示为警告并写明目标；格式错误、白名单失败、TLS 错误和 Worker 明显错误仍显示错误。诊断不改区服、快照、账号、设置或 Battle.net 状态。

4. **导出诊断包（约 1 分钟）**
   - 操作：点击“导出诊断包”，用压缩工具打开 ZIP。
   - 预期：包含 `diagnostics.json`、`diagnostics.txt`、`environment.txt` 和 `logs/`；日志 entry 都在 `logs/` 下。不得出现 Bearer、token、cookie、password、GITHUB_TOKEN、CLOUDFLARE_API_TOKEN 的完整值，也不得出现绝对路径形式的 ZIP entry。

5. **打开 Snapshot（约 30 秒）**
   - 操作：进入“区服快照 / 快照管理”。
   - 预期：只显示 CloudLight Blizzard 管理的 generation；模式、来源与目标、状态、文件数量、大小、创建时间和最近使用状态清楚，页面打开不删除或重写快照。快照状态直接反映目录、记录文件、文件数量和 Generation 状态。

6. **打开 Switch Preview（约 1 分钟）**
   - 操作：进入区服页面，点击“切换到国服/国际服”生成预览。
   - 预期：显示 Plan 的来源、目标、恢复/删除/保留数量、预计字节、磁盘空间、Battle.net 状态、警告和阻断项。生成预览不改游戏目录、快照、product DB、settings 或 Active Generation。

7. **取消（约 30 秒）**
   - 操作：在预览窗口点击“取消”。
   - 预期：窗口关闭，没有切换、没有重启 Battle.net、没有写入新的区服状态；再次打开预览会重新显示当前状态。

8. **Drops 状态卡（约 1 分钟）**
   - 操作：进入 Drops，观察 SOOP、Twitch、YouTube 状态卡和最近事件。
   - 预期：卡片显示连接阶段、Worker 健康、最后心跳/成功时间和重试倒计时；状态变化后 UI 不报 `CollectionView` 后台线程异常。

9. **立即重试（约 1 分钟）**
    - 操作：在可复现的网络失败或等待重试状态下点击“立即重试”。
    - 预期：只唤醒当前重试循环，不创建第二个 Worker/重试循环；成功后倒计时消失，恢复次数和事件记录更新。

10. **Toast test（约 1 分钟）**
    - 操作：到“设置 → Windows 通知”确认启用；触发一个可控的更新结果或 Drops 状态变化，之后再次快速触发同类失败。
    - 预期：安装版能收到对应 Toast；portable/开发运行即使系统 Toast 注册不可用也不启动失败。连续失败只通知一次，最终恢复只通知一次；Toast 异常不阻断业务。关闭通知后不再发送。

11. **设置 → 更新通道（约 30 秒）**
    - 操作：打开设置，切换 Stable/Beta（如界面提供），再切回 Stable。
    - 预期：选择保存且不改版本号；通道切换不会自动启动重复下载或重复安装器。

12. **检查更新（约 1 分钟）**
    - 操作：点击“检查更新”。
    - 预期：显示最近检查时间和结果。安装包只有在元数据包含合法 `sha256:<64 hex>`、大小、白名单 URL 且 SHA-256 校验成功后才允许启动；取消/重试不会启动多个 installer 或多次退出应用。

13. **窄窗口（约 30 秒）**
    - 操作：将窗口调整到接近最小宽高，在账号、Diagnostics、Drops 和 Snapshot 间切换。
    - 预期：不出现截断到无法操作的按钮、横向溢出或页面崩溃；长路径、错误和诊断文本可滚动/换行。

14. **Windows 125% / 150% DPI（约 2 分钟）**
    - 操作：在 Windows 显示设置分别使用 125% 和 150%（必要时重新登录/启动程序），重复检查账号、Diagnostics、Switch Preview、Drops 和更新对话框。
    - 预期：文字、按钮、Toast、列表和进度条不重叠；高 DPI 下仍能看到取消/关闭/开始切换按钮；VisualTree selftest 与 WPF binding selftest 保持通过。
